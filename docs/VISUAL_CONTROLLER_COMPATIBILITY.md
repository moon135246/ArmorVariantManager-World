# 变身插件显隐优先级（1.3.2）

正式版 1.3.2 沿用已通过实机验收的 Beta.2 功能逻辑。

在「设置 → 插件兼容」勾选「差分管理器优先于变身插件」，默认开启，修改后立即保存到 Settings.cfg。

| 当前查询 | 开启：差分管理器优先 | 关闭：变身插件优先 |
| --- | --- | --- |
| 变身插件接管并返回显示／隐藏 | 使用差分当前规则，可覆盖显示和隐藏 | 完整保留变身结果，可覆盖差分显示和隐藏 |
| 变身插件未接管 | 保留游戏判断，并应用差分隐藏 | 同左 |
| 差分控制暂停、未匹配装备或身份校验失败 | 保留原查询结果 | 同左 |

仅影响差分管理器已匹配的装备实例。场景、武器及其他未匹配对象保留原查询结果。调用者后续的游戏淡出判断继续执行。队友沿用既有的独立实例／只读预设规则，优先级是本机全局设置。

## 实现与边界

受支持游戏版本为 Steam 15.23.00 / build 421810。基础 `visual_controller_v5.dll` 和 [进阶版 1.4.0](https://github.com/Mi1ice/MHWI-VisualControllerExtended) 共用 RVA `0x222FC90` 查询函数。进阶版可以延迟挂钩，命中规则时直接返回，不继续调用下一层。因此只在原入口叠加隐藏既不能强制显示，也会受加载顺序影响。

Beta.1 只覆盖了唯一直接 CALL，但实测角色装备通过虚表 `+0x188` 调用查询，导致没有控制效果。Beta.2 同时处理 RVA `0x26DC30D` 的五字节 CALL 和 `.rdata` 中已对齐、值精确等于查询入口的静态函数指针（包括角色及装备虚表引用）。函数引用原子替换后恢复原页保护，不克隆对象虚表、不改变角色身份；所有路径均调用当前完整查询链；在线程局部跟踪中，于原函数无条件前序之后的 RVA `0x222FCAD` 标记是否进入游戏正文。受支持控制器没有进入正文即返回，表示本次实际接管；进入正文表示透传。优先级处理发生在调用者恢复执行游戏淡出检查之前。直接调用点与原生正文观察点由 SafetyHook 保存／恢复寄存器并重定位，安装前校验查询签名、正文和调用点签名；不修改第三方 DLL 或模型文件。

这种判定直接使用插件实际结果，不复制进阶 INI、血量锁存或武器条件，不以固定 ID 白名单猜测命中。进阶规则重载、开关、条件缺失和自定义 ID 继续由原插件决定。识别的 DLL 文件名为上述两个标准名称；重命名 DLL、未来改用其他控制路径或调用原函数后再改写结果的插件不在本次验证范围内。

Settings 129 在 SET 行末保存优先级布尔值，兼容读取 117／121／122／123／124／128。旧配置读取后默认开启，但不在读取时改写；后续保存升级格式。原版本无法读取 129，回退需恢复升级前 Settings.cfg 备份。装备 WDP 格式没有因本功能升级。

## 验证

2026-11-10 离线通过 873 项：真实 SafetyHook 调用链检查 492、存储 117、实际设置页面与更新日志 130、联机策略 69、快捷键 65。调用链使用自行构造的执行代码，三种基础／进阶先后顺序各 164 项，覆盖直接与虚函数两条路径及只读表页保护恢复；覆盖 ID 30、自定义 ID 500、未命中、停用、显示与隐藏双方优先、原生剔除、后续淡出、嵌套查询及四线程独立结果。

本机已只读核对 DX12、基础 DLL 与 ID 30／31 外观；原安装版本与工作区历史记录存在差异，已按实际 DLL 和配置备份。Beta.1 的首次实测未通过；Beta.2 基础版游戏内验收通过，用户确认两种优先级与显隐双向覆盖均正常；进阶 1.4.0（本地参考源码构建、49 条规则）共存下同样通过，并验证了面板总暂停与恢复；实机覆盖 ID30／31 外观；其他武器、血量锁存、自定义 ID、进阶重载及长期联机仍以离线覆盖为主，未逐一实机验收。进阶默认 Ctrl+F9 与 WorldDiff 暂停同键，分别控制时使用面板或进阶 /vc on、/vc off，或自行调整进阶 INI 热键；本次不改写其默认热键。

建议实机验证：默认开启时收刀／拔刀均保持差分选择；关闭时恢复 ID 30／31 变身；在关闭状态让差分隐藏一个变身插件会显示的网格，确认外部显示仍优先；重新开启时该网格恢复差分隐藏。另需验证总暂停、重启后设置保留，以及进阶规则、锁存、Ctrl+F5 重载和 Ctrl+F9 开关。
