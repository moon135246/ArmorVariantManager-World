# 通用网格溶解（Beta 研发）

验收目标是玩家安装差分管理器后，已有服装可以使用溶解。服装作者无需重导模型、修改 MRL3、添加 TEX、指定贴图槽或制作第二份服装。首个效果为「银紫窄边」；后续效果共用同一套网格识别、过渡时钟和渲染入口。

## 可安装的通用测试版

### 原版装备的风格坐标

DX12 材质在颜色与深度阶段都提供主纹理坐标时，插件可直接使用原装备的 UV 展开绘制三种风格。具备匹配几何文件的 MOD 优先沿用绑定姿势坐标；找不到独立 MOD3 或该行几何不可用时，改用材质坐标。两条路径复用风格着色与过渡进度。材质阶段不齐全时继续使用通用显隐。日志中的 `source=material-uv` 和 `source=mod3` 可区分坐标来源。

### 溶解风格

溶解风格测试版 Beta.2 增加第三项「墨染洇花」。几处湿墨随进度扩散并连成片，青绿湿边、深靛色墨层与断续水痕沿同一片绑定姿势表面推进。反向时沿相同纹路收回。沿用原有曲面细分路径，深度与颜色共用覆盖函数，颜色阶段再叠加湿墨。无需为装备配置预设、UV 或额外贴图。

设置格式 132 新增墨染选项，兼容格式 131 的银紫流光、琥珀裂晶及其已保存时长。1.4.0 首次使用默认开启琥珀裂晶，完整过渡时长为 0.9 秒。可用 `test_dissolve_dx12.exe <fixture> hardware --ink-motion` 或 WARP 回放显示、隐藏和半程折返。

「设置 → 网格溶解」使用与界面风格相同的下拉控件，选项依次为银紫流光（月弧）、琥珀裂晶和墨染洇花。从设置格式 131 起，风格保存在全局设置中；读取 130 及更早的受支持配置时采用默认风格琥珀裂晶，保留已有时长。三种风格使用同一个时长和过渡时钟。开始一次显隐时确定风格，中途更改下拉选择时，当前动作及中途折返继续使用原风格，下一个独立动作采用新选择。

琥珀裂晶按已识别网格的绑定姿势坐标生成稳定的三维晶格。插件将归一化坐标紧凑保存到每个三角形角点上；过渡期间复用原服装顶点与材质着色器，用自适应曲面细分在深度和颜色阶段裁切晶片，再在已经通过深度测试的颜色表面绘制金线和蜜橙色外缘。无需配对网格、专用 UV、贴图或玩家预设。无法使用晶格管线时沿用通用网格显隐。

本地测试构建使用 `build.cmd silver-beta`。离屏回放入口为 `test_dissolve_dx12.exe <fixture> hardware --amber-motion`，也支持 WARP。实机以 `Amber crystal: color draw` 的资源、行号、起始隐藏进度和目标进度与玩家目视反馈交叉核对。

### 逐像素银紫流光 Beta.2 / Beta.3

`build.cmd silver-beta` 编译当前 Beta.3。它沿用原来的本机装备识别、全局开关和时长。兼容管线用原服装顶点着色器和骨骼，按绑定姿势计算每个顶点到溶解边界的有符号距离。光栅化器在三角形内部裁切，像素着色器沿可见侧画银白线芯和紫色外缘。Beta.3 增加了线芯宽度和紫边的饱和度，给纯紫段留出更宽的区域，再向服装原色渐隐。屏幕导数控制宽度，模型空间的宽度上限限制小配件上的着色面积。

游戏保留其原有根签名。插件为已验证的四表布局建立扩展签名，按调用所用命令列表记录材质表和资源堆。绘制前核对原根签名、着色器实际使用的表和描述符范围；结束时恢复原签名、各表和原材质管线。已在插件加载前建立的两种布局通过 D3D12 返回的同一签名对象匹配。材质或模型不满足条件时仍可使用前一版空间色带或通用显隐。

实机核对应查看 `Silver pixel: color draw` 的模型路径、网格行和 `from/to`。其中 0 表示完全可见，1 表示完全隐藏。起点位于 0 与 1 之间的反向事件可与目视结果核对。仅有 `material ready` 表示材质已准备。离屏回归可用 `test_dissolve_dx12.exe <fixture> hardware --silver-motion` 或 `warp` 检查单网格显隐和半程折返。

### 美化前基线与首版空间色带

2026-11-11 的美化测试使用 `build.cmd silver-beta`，产物在 `build/silver-beta/WorldDiff.dll`。设置仍使用全局开关和过渡时长，单独切网格即可使用。冰狼腰部已在 Steam DX12 会话验收显示、隐藏和中途反向，用户确认银紫边清楚、折返连续。

工作线程按本地角色已经穿戴的资源路径读取 MOD3，核对实时网格行和原始索引范围，按绑定姿势计算高度与起伏。排序只改变三角形提交顺序，显示与隐藏使用同一组阈值。此次游戏实测命中游戏原有根签名路径，深度与颜色沿用游戏材质，银白和淡紫在通过深度相等测试的窄带叠加到颜色附件 0 的 RGB。颜色路径需要兼容的六附件装备管线。未能读取几何时沿用先前的通用三角形显隐。当前每行独立归一化，多部位共用空间边界仍待开发。

空间三角形路径和逐像素裁切路径的验证分别记录。冰狼实机使用空间三角形路径。冰狼与浴场腰部网格在 RX 9070 与 WARP 上分别完成 93 帧离屏回放，包括 450 ms 处反向和回到可见端点。离屏预览使用测试材质和私有遮罩。进入游戏后使用哪一路径应以 `Silver flow: spatial silver band` 或逐像素 `spatial draw` 的实际记录为准。

设置 → 网格溶解可独立开启或关闭效果。过渡时长支持滑动或直接输入 0.05–10.00 秒，默认 0.90 秒。显示和隐藏使用同一时长，反向操作从已经显示的部分继续。玩家偏好保存到 Settings.cfg 130；117–129 的既有设置仍可读取，WDP 文件保持原格式。

正常构建与本地 dissolve-beta 构建都按本机角色当前装备和最终规则自动选择子网格。渲染器按三角形将原索引范围分成至多十二段，每段依进度保留一部分，在游戏原材质、原顶点输入及原颜色／深度管线上绘制。这样可保留服装自身的透明裁切和骨骼，单独一行即可显示或消失。无须服装的 UV、源文件、同拓扑的替换行、专用贴图或预先登记的部位与行号。视觉顺序取决于原模型的三角形排列。银紫窄边仍为独立研发项。

当前适用范围为 Steam 421810 的已识别 DX12 本机装备索引绘制。引擎模型常量标识、实例、索引视图和唯一网格范围用于定位；游戏或其他高优先级控制器所阻止的绘制继续服从原显隐。切换角色、装备或重开效果时直接建立新基线。后文的试验标记、原始采样以及七对体型测试描述研发阶段，玩家安装通用测试包时均无需配置。

## 产品行为

- 在差分管理器中选择「即时切换」或已经可用的溶解效果。全局外观设置归玩家所有；普通服装和已有 WDP 沿用现有工作流。
- 根据切换前后**最终可见**的网格集合决定加入和退出的目标。重合网格保持原样。预设、分组、条件和快捷键应使用同一决策路径。初次装载、目标失效、临时关闭效果或渲染后端无法处理时，服从已有显隐规则。
- 按角色实例及实际子网格标识定位。两个网格即使共用一个材质，也应能只过渡其中一个。中途反向切换从当时的进度继续，结束时交回正常绘制状态。
- 银白线芯、淡紫外缘只覆盖正在消散的窄带。上一轮有声袖子实测的 1.2 秒仅作美术对照。效果选择与时序独立；默认时序待通用路径上实测后确定。

## 当前验证项

现有查询可以同时取得角色实例、网格记录和绘制上下文。诊断构建在本地主角的查询期间复制数据，检查上下文中的网格引用、索引，以及模型淡出与一个候选字段的变化。它不修改这些值。一个查询命中并不等于一个已经确认的 GPU draw，也不能确认某个字段控制最终像素。

先用同一角色、同一实例的多网格做远镜头、近镜头、拉远的对照。若候选值随相机变化，应继续跟踪它在哪个阶段复制到绘制命令，验证单网格能独立生效。若不随相机变化，则保留网格身份链，单独定位绘制常量的提交位置。时间相关性不可代替因果验证。

渲染后端需要将空间遮罩作用于目标网格的正常绘制，兼顾深度、阴影和材质自身的透明裁切。位置和强度数据通过插件传递；已有材质负责自身外观。跨材质验证至少包括实际绘制的 PL_Mt 网格和非 PL_Mt 网格。仅在材质表里列出模板不能作为通过证据。还需检查同材质相邻网格、换装、遮挡、显隐优先级和无过渡时的开销。

## 只读采样

1. 使用 `build.cmd dissolve-probe` 生成 `build/dissolve-probe/WorldDiff.dll`。常规构建不包含采样器。
2. 使用诊断 DLL 启动游戏，进入可观察本地主角的场景。把一个空文件 `dissolve-probe.once` 放入游戏的 `nativePC/plugins/WorldDiff/`。工作线程消费该文件后开始记录 30 秒；可再次创建文件重复测试。
3. 先保持人物完全可见数秒，推近相机至完全隐藏，再拉远。记录同目录下 `dissolve-probe-进程号-时间.csv`。同部位同网格最多每 12 ms 采一次；记录时间是采样时间，不是引擎帧号。末行记录因锁竞争或缓冲区已满而丢弃的样本数。
4. 仅对 `readable=1`、`mesh_ref_matches=1`、`packet_index=mesh` 的行做数值对照。按实例、部位、网格分别检查 `model_314` 与 `packet_64`；保留不匹配比例和观察不到的阶段。角色不进入绘制查询时，无样本不能解释为淡出值等于零。

可用 `python tools/analyze_dissolve_probe.py <采样文件.csv>` 汇总每个网格的样本。输出包括候选值的范围、有效性和与模型值一致的次数。

当前诊断 DLL 只用于定位通用入口。「银紫窄边」尚未接入正式游戏菜单。按衣服烘焙的本地贴图仅用于对照美术效果。

## DX12 离屏网格试验

在仓库根目录使用自有 MOD3 文件生成测试数据。两个行号从零开始，须来自同一材质槽和同一 LOD。生成文件包含模型几何，请保存在本地构建目录。

```bat
if not exist build mkdir build
python tools\dissolve_mesh_fixture.py "<本地模型.mod3>" 5 13 build\inner.pair
tools\test-dissolve-dx12.cmd build\inner.pair hardware
build\test_dissolve_dx12.exe build\inner.pair warp
```

测试在两种绘制顺序下比较完全显示、完全隐藏和 20%、50%、80% 进度的颜色与 D32 深度。两张网格共用同一测试材质，分别测量不透明和透明裁切。效果按绘制的三角形编号从独立缓冲区读取原模型的绑定姿势坐标。

克莱尔腕部的实机绘制使用 D32_FLOAT 或 D16_UNORM，两种格式都没有模板位。当前原型在常规几何画完后，以只读深度重画目标网格的原材质到私有 R8 遮罩。遮罩清为白，通过原材质裁切及深度测试的像素用固定功能混合写成黑色。独立的边缘着色器只处理这些像素。该路径在单目标、不透明或透明裁切、单采样、写入深度的测试场景中验收。接入时需要辨认延迟渲染各阶段，避免重新执行有写入副作用的着色器，并为多个过渡目标、半透明混合和重合表面处理归属问题。

## 原生着色器管线适配

克莱尔女腕的第 0、2 行共用 Standard_Mt，第 1 行使用 PL_Mt。在同一真实捕获帧中，三行的索引起点、数量、基础顶点和绑定索引缓冲区全部对应。第 0、2 行命中三个管线状态，第 1 行命中两个。绘制句柄仅对该捕获文件有效。

从本地帧中提取 VS、PS、根签名和输入布局，在 VS x64 开发者命令行编译验证程序。布局文本首行依次为深度格式、颜色目标数、各颜色目标的 DXGI_FORMAT 数值和输入元素数。随后每行记录语义名、语义索引、格式、槽、字节偏移、输入分类和实例步长。

```bat
cl /nologo /std:c++latest /O2 /W4 /EHsc /D NOMINMAX tools\test_dissolve_native_link.cpp /Fo:build\native-link.obj /Fe:build\native-link.exe /link d3d12.lib dxgi.lib d3dcompiler.lib
build\native-link.exe vs.cso ps.cso root.cso layout.txt hardware
```

程序先创建原着色器管线，再按 VS 输出生成保留原语义的几何阶段，在根签名末尾增加 GS 专用的位置缓冲和进度参数。对于有颜色输出的管线，也验证私有 R8 目标的创建。这里只验证管线创建及阶段链接。当前游戏 DLL 仍未提交这些溶解绘制。玩家安装和使用差分管理器无需安装捕获工具。

## B 时序与体型交接

诊断构建从已经解析的本机角色显隐策略派生过渡。淡出 400 ms，配对淡入从 280 ms 开始并持续 300 ms，单独显示立即起步。策略刷新沿用正在执行的过渡；中途改向从当时的隐藏比例继续。角色、装备、网格表或策略有效期失配时丢弃过渡。诊断日志的 planned_hidden 是计划值。present_tick 标记其取样使用的 Present 时钟。first_index、index_count 和 base_vertex 来自查询行。该记录不能作为游戏已经执行新 GPU 绘制的证据。

对原始腕部 Body_Small 和 Body_Big，独立空间溶解与旧 alpha 交接在视觉上差异很大。两张网格均有 15535 个顶点和 27378 个三角形，局部索引序列相同。离屏配对试验使用 Small 的绑定姿势坐标驱动双方的边界，各自保持自己的顶点。两边分别保留边界两侧，按两行的可见权重计算交界线位置。实际换形集中在 B 方案的 120 ms 重叠窗口。只有显式指定并验证对应关系的样本使用此模式。

可用已有的真实 MOD3 再现两种交接。GPU 测试程序从仓库根目录运行，输出 36 帧 384 × 384 的 RGBA8 读回图像。

```bat
python tools\dissolve_mesh_fixture.py "<本地模型.mod3>" 0 11 build\preset.pair --preset-pair
build\test_dissolve_dx12.exe build\preset.pair hardware build\independent.rgba
build\test_dissolve_dx12.exe build\preset.pair hardware build\shared.rgba shared
```

## 回放实机切换时序

在普通 DX12 游戏会话中触发管理器诊断采样。在相同的已穿戴模型上执行一次预设往返。使用原始 CSV 中的实例号和两行索引提取同一 Present 时间的配对样本。两个网格有明确的三角形对应关系时，可使用共用交界线回放。

```bat
python tools\analyze_dissolve_probe.py sample.csv --pair 2 0 11 --instance fe1d7d60 --replay-out build\paired.tsv
build\test_dissolve_dx12.exe build\preset.pair hardware --replay build\paired.tsv
```

实例号仅对该次采样有效。配对会排除缺行、无有效进度、网格引用不匹配或同一时间读数冲突的样本。回放对比未接管时的即时显隐，以及已同时准备好两边裁切资源时的端点与重叠画面。游戏目前只提供前一种结果。场景后端需要在隐藏查询决策之前确认目标实例、索引范围和所有必要绘制阶段均可接管。

## 原场景材质绑定

已验证的两个游戏根签名各有四张描述符表。原 VS 和 PS 需要同时使用游戏当前的资源堆和采样器堆。在调用方已知原始根签名、PSO 和各表句柄时，TryRecordMaterial 逐表核对句柄对齐、有效范围和连续长度。检查通过才切至扩展根签名，重新绑定原表，提交裁切绘制，再恢复原根签名、各表和 PSO。尚未支持的根参数布局保持原有绘制。

R8 遮罩目前在 GPU 上按 GetCopyableFootprints 给出的行距复制到缓冲区。银边 PS 使用根 SRV 按行距取样，避免用私有描述符堆替换游戏材质的资源堆。代价是每个活动遮罩增加一次 GPU 拷贝，游戏帧耗尚待接入后测量。原始 VS 配合银边 PS 的管线创建已分别在 Standard_Mt 和 PL_Mt 颜色阶段验证。

这些条件覆盖命令记录时的绑定完整性。查询侧仍需由真实场景提交方确认本实例、本行及相关阶段能接管。当前游戏的 Present 回调只提供交换链和队列，管理器的界面命令列表不能代表游戏绘制装备时的命令列表。

普通 DX12 会话的腕部小杯往返已核对到实际场景绘制。目标侧从本地腕部对象、MOD3 网格行及模型资源的索引视图取得身份；绘制侧独立取该次 CBModel.iUnitAddress、实际索引视图以及 DrawIndexedInstanced 的参数。Body_Small 和 Body_Big 使用相同索引视图且索引数量相等，起始索引分别为 0 和 346248。相同材质、相同 PSO 或只有索引数量都不足以选中网格。

MeshDrawTarget 在准备效果时要求该索引范围仅对应一个模型行。TryRecordMaterial 在记录第一条命令前核对模型实例、完整视图、索引范围和实例数。本次腕部样本包括两种深度附件上的纯深度绘制和一组绑定六个颜色附件的绘制。后者的原 PS 写出六个 SV_Target，直接覆盖这些输出会改变游戏交给后续光照阶段的数据。游戏内的最终银边合成仍待验证。

## 原场景列表提交验证

Steam 421810 的 DX12 测试构建在显式的 30 秒采样期间启用原场景索引提交入口。它从当前记录线程的 VS b3 绑定读取已验证的 CBModel 常量，核对本地角色部位、模型索引缓冲视图及唯一网格范围，再在游戏当前命令列表用原参数提交一次绘制。其他绘制沿用游戏路径。结束后停用该入口。随查询 CSV 一起生成的 dissolve-scene-进程号-时间.csv 记录已提交的绘制、当时的 PSO、根签名与附件。末行 visited 是访问入口的总次数，dropped 是未能写入日志的命中次数。

腕部正常 Steam DX12 实测已覆盖小杯 → 大杯 → 小杯的三次绘制阶段，用户确认外观和操作正常。本轮沿用原有可见性结果及材质。正式溶解需要在当前命令列表上准备裁切资源、恢复实际描述符表，并在查询侧保留能被各阶段接管的出场网格。

## 配对体型的原材质空间交接（开发构建）

在本地测试标记 `nativePC/plugins/WorldDiff/dissolve-handoff.test` 中依次写入部位号、两行网格号、已穿戴模型的相对路径（不含扩展名）和可选时长毫秒。每行选择一对，时长取首行第五项。当前预设在场景中可见后，工作线程即可为首次切换准备索引缓冲。工作线程只读 MOD3，核对 LOD、顶点与面的对应关系，以及游戏中的布局、实例和索引范围。已核对 32、36、40、44 字节四种顶点布局。初始一行实际绘制过两组深度和一组六颜色附件管线后即可就绪；另一行首次出现时逐次核对自己的管线、根签名、深度附件、角色和索引视图。单个测试会话为每对网格保留不可变上传缓冲，直至进程退出；移除标记可停用本次试验。

验证通过后，两行共用第一行绑定姿势上的空间排序。每个 Present 一次发布所有已准备行的进度；互换预设时两边绘制互补的三角形集合，单独显示或隐藏时各行按自身目标推进，沿用各自原有的骨骼、材质及深度管线。结束时恢复原始索引及普通显隐；中途反向从当前进度继续。诊断采样期间，场景 CSV 记录每个目标实际提交的索引数量、共用进度的序号和分界索引。这个序号标记插件在 Present 发布的快照。审计同一快照下两行在三个阶段的互补范围可用 `python tools/analyze_dissolve_probe.py <场景CSV> --handoff-scene 2 0 11`。

第一轮实机沿用原 B 时序，两方向各只观察到 109 ms 的中间值，用户反馈像瞬切。新试验给这对网格独立的共用时钟，按对应顶点位移加权，默认 900 ms。测试标记的第五个字段可在游戏运行时调整为 100–5000 ms，对下次换形生效。未配对的网格仍用原有策略。此步的空间边界以完整三角形为单位，逐像素裁切与银紫窄边属于后续材质管线工作。

七对试验将 14 个变化网格加入同一次交接。身体保持原三角形对应。领口、裙装和袜身有 1297 个四边形在两种体型中换过对角线；逐顶点比对主 UV，按四个共同顶点及一致的有向外边界识别两侧各自的两个三角形。切换时整面一起分配，并保持各侧原始绕序。采样请求可选填 1–90 秒，空文件默认 30 秒。
