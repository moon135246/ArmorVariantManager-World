# 差分管理器 · 怪物猎人世界版 1.0.2

本版可以按**模型中的材质**或**独立子网格**实时隐藏和恢复。所有网格的 Group_ID 都为 0 时，也可以分别控制。无需 REFramework，无需修改 MOD3/MRL3，无需给网格分配新 Group_ID。

## 开始使用

1. 保留本文件夹的完整内容。双击 **启动管理器.cmd**。
2. 打开游戏并进入角色所在场景。管理器会自动连接已加载的插件；也可点“连接游戏”即时加载同目录 DLL。
3. 在左侧选择带黑点的已观测模型，或勾选“只看当前观测到的模型”。
4. 选择“按材质选择”或“按子网格选择”，**勾选隐藏，取消勾选恢复游戏显隐**。

当前电脑已经安装插件并完成现场连接，本次游戏无需重启。未来启动游戏时，Stracker's Loader 会从 `nativePC/plugins/WorldDiff.dll` 自动加载插件。

若迁移到另一台电脑，先安装 Stracker's Loader，再运行“安装到游戏.cmd”。默认游戏目录为 `F:\SteamLibrary\steamapps\common\Monster Hunter World`；其他目录可以在 PowerShell 中运行：

```powershell
& '.\安装到游戏.ps1' -GameRoot '你的游戏根目录'
```

## 材质、子网格与部位

- **材质模式**：以“模型路径 + 材质名称哈希”保存规则，同模型内使用该材质的多个子网格一起控制；新 LOD 或模型重新加载时仍能匹配。
- **子网格模式**：以“模型路径 + 子网格序号”保存规则，可以分别控制共用一个材质的网格。MOD 作者重新排列网格后，请重新检查这些规则。
- 材质隐藏后，在子网格模式取消某个网格的勾选，可以把它设为跟随游戏的例外。重新切换该材质的勾选会清理它的子网格例外。
- “身体槽、手臂槽、腰部槽”等是游戏的装备槽位。MOD 作者可以把头发、衣服等放在任意槽中，应以材质名和实际效果为准。
- 程序保留游戏与其他已存在显隐插件的原结果。“恢复显示”表示恢复游戏控制；LOD、装备状态等原本不允许显示的内容不会被强制画出。

实时材质名直接来自游戏模型资源。即使没有散装 MOD3，也能显示已进入绘制查询的装备材质；`nativePC` 中的 MOD3/MRL3 解析则用于未加载模型的清单与 MRL 序号辅助信息。材质哈希不是子网格序号，MRL 序号也不等于 MOD3 的 materialID。

## 保存、恢复和预设

修改会自动保存。输入预设名称，点“保存命名预设”；以后选择名称并点“应用此预设”。预设包含所有已设置模型的规则，换回同模型时会自动重新应用。

“恢复此模型”清空选中模型的规则；“全部恢复显示”清空当前规则；取消“启用显隐控制”可临时暂停所有隐藏并保留规则。最小化管理器会继续应用设置。关闭管理器会恢复游戏显隐，重新打开后再应用已保存设置。进程异常退出或失去心跳时，插件在 5 秒内停止隐藏。

“全部恢复显示”不删除已命名预设。配置文件是程序运行目录中的 `WorldDiff102.ini`，备份这个文件即可保存个人设置。

## 启动器与文件位置

此工作区继承了旧尝试留下的 Low 完整性标签，直接在这里运行 EXE 会使它无法连接正常权限的游戏。因此请使用 **启动管理器.cmd**，它会在用户应用目录创建正常运行副本：

```text
%LOCALAPPDATA%\WorldDiffManager\1.0.2\
```

运行副本包含 EXE、DLL、个人配置与日志。“打开程序目录”可直接找到实际目录；在打包桌面应用内启动时，Windows 可能把它映射到该应用的 LocalCache。工作区保留源码和发布包。把发布包解压到普通文件夹后，也可以直接运行 EXE。日常使用无需管理员权限。

安装脚本只部署 `nativePC/plugins/WorldDiff.dll`。如已有其他版本，会先备份并要求退出游戏后更新；不会改动模型、材质或存档。卸载时正常退出游戏，再移走该 DLL 即可。

## 当前范围

- 已对当前 Iceborne 游戏程序的显隐函数签名与模型布局完成验证，实测为 DX12。插件不使用 D3D 覆盖层；其他程序版本若签名不符，会停止安装钩子并在界面/日志报告。
- 控制范围是玩家装备模型路径 `pl/f_equip` 与 `pl/m_equip`。同路径的所有本机绘制实例会受到同一规则影响，不区分本地猎人与穿着同模型的其他猎人。
- 材质模式的最小单位是使用该材质的子网格集合；子网格模式的最小单位是游戏模型中的一条网格记录，不能拆开同一记录里的若干三角面。
- 当前版包含手动显隐与命名预设，尚未移植荒野版的血量、武器状态等自动条件。
- 单次游戏最多保留 8192 条观测记录。极长时间大量换装后如显示记录已满，请重启游戏；未识别目标会继续跟随游戏。

## 构建与验证

源码在上级 `src`；需要 Visual Studio C++ x64 工具链。退出游戏后运行上级 `build.cmd` 构建 DLL 与 EXE；只更新界面可用 `build.cmd --ui-only`。

解析器 32 项检查通过；材质规则、显示例外、运行时清单及中文配置/预设往返测试通过。现场已验证 `DSM_7_Sleeves` 单独消失、撤销恢复，以及失去心跳后的自动恢复。详细截图、数据与逆向证据在上级“验证记录”文件夹。
